Entregável — Exercício 2.1

Projeto: NovaTech Assistant API | Configuração e Validação de Servidores MCP

1. Mapeamento dos Servidores MCP

Para atender as necessidades do assistente NovaTech e garantir a separação rigorosa de escopos e privilégios de acesso, a arquitetura de contexto local foi estruturada com os seguintes servidores via Model Context Protocol:

  • fs-codigo: Mapeia as pastas de código-fonte (./src e ./tests), permitindo que o agente autônomo analise, escreva e edite a base de código do Query Endpoint de forma independente.
  • fs-leitura: Mapeia os repositórios de documentação corporativa (./docs) e corpus de base de conhecimento para RAG (./data). Esse servidor possui escopo estritamente de leitura, fornecendo contexto seguro sobre regras de negócio e SLAs.
  • project-memory: Servidor de grafo de conhecimento que atua como memória de longo prazo da arquitetura. Permite ao agente registrar, ler e atualizar decisões arquiteturais e padrões de projeto essenciais.

2. Arquivo de Configuração Base (.mcp/mcp.json)

O arquivo de configuração abaixo representa o padrão de repositório oficial, formatado com o comando npx em escopo global (e sem dados relativos a usuários locais). 4. Análise Crítica de Riscos e Segurança

No desenvolvimento com agentes baseados em ferramentas, especialmente em ecossistemas empresariais locais usando o Model Context Protocol, três principais vetores de vulnerabilidade devem ser geridos:

1. Acesso Indevido a Diretórios Externos (Directory Traversal)
O risco primário onde o agente tenta inferir acesso a arquivos ou componentes confidenciais localizados em repositórios vizinhos, chaves de API, variáveis de ambiente (como .env) ou mesmo dados restritos do sistema do usuário hospedeiro.
Mitigação (Aplicada): Utilização da política de escopo fechado do server-filesystem do MCP, listando explicitamente o limite em pastas alvo como argumentos de sandbox (./src e ./docs). Nenhum comando externo que saia dessa árvore é interpretado como válido pelo servidor.
2. Sobrescrita e Mutação Acidental de Código Base
Durante tentativas iterativas e autônomas (loops) de resolução de código, há a ameaça do agente deletar artefatos essenciais ou introduzir bugs de maneira oculta se não constrangido devidamente.
Mitigação: Imposição nativa de Human-in-the-loop na camada de execução (interface do Cline), exigindo aprovação binária humana direta para que ações mutacionais como write_file ou comandos de terminal de sistema operacional possam ser performados. E, estruturalmente, separação total entre repositórios restritos de leitura (fs-leitura) e escrita (fs-codigo).
3. Exfiltração de Propriedade Intelectual (Vazamento de Contexto)
Dada a natureza de ingestão de arquivos locais inteiros como logs de janela de contexto do LLM, os dados corporativos processados (como chaves soltas no meio do código, credenciais fixadas ou arquiteturas sigilosas) fluem por APIs para treinamento de modelos públicos da nuvem.
Mitigação: Manutenção de provedores com licença Enterprise/Zero-Retention (onde modelos proíbem treinamento cruzado de payload processado) ou integração sistemática de ferramentas de DLP (Data Loss Prevention) e sanitização baseada em máscaras na pipeline local antes da transmissão.
